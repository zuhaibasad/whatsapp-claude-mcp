# 2026-10-22: 0.3.0, image OCR and the ChatAI rebrand

## Discussed (no code)
- **Directory listing / claude.ai / phone:** the Connectors Directory needs a remote OAuth server, and a Baileys-based product is likely to be rejected there (WhatsApp ToS). The phone and claude.ai can be served by **Dispatch** (Cowork) or **Remote Control** (Claude Code) against the local install, with no relay. This is untested: does Cowork see local `.mcpb` extensions? A relay/tunnel is the fallback only. See [[HANDOFF]] next steps.
- A friend installed 0.2.0 on their PC: setup, brief and questions worked. Images were not read, which led to this release.

## Built
- **Images + local OCR** (see the DECISIONS entry of 2026-10-22):
  - schema v4 `media` table with FTS;
  - `src/daemon/media.ts` worker, `src/daemon/wa/media-download.ts` (`downloadContentFromMessage` only);
  - `src/daemon/ocr-fields.ts`;
  - the `image` field on messages;
  - `whatsapp_read` action `media` (with `include_image`);
  - config `media_download`, `media_ocr` and `media_max_mb`;
  - `.mcpb` pruning for tesseract.
- **Rebrand:** ChatAI for WhatsApp, slug `chatai` everywhere. New logo `docs/assets/logo.svg` and `packaging/mcpb/icon.png`. Indigo palette in the UI, the README visuals and 8 regenerated screenshots.
- **GitHub (Sonnet worker):** description and 15 topics set. Draft release **v0.3.0** with `chatai-0.3.0.mcpb` attached; the old v0.2.0 draft was deleted.
- **Keychain:** every `wa-bridge`/`chatai` entry was removed (the user had already unlinked their phone).
- Checks: `npm run check` (396 tests), `build:mcpb` (23.7 MB), `smoke:mcpb`, and OCR run from the packaged build. All pass.

## Open
- Local `main` is ahead of origin; not pushed. The draft release targets `main`, so push before publishing.
- Licensing (GPL-3.0 libsignal) still blocks a public release.
- OCR is not tested on real bills. Not covered yet: PDFs, Urdu OCR, the proxy for media download.
