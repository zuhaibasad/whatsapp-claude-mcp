# T11: chat selection backend (scope changed: no terminal picker)

The interactive TUI picker was cancelled. A browser/MCP-App UI will call this backend.

## API
- `src/config/selection.ts`
  - `computeRules(all: ChatChoice[], selectedIds, current?: {includeGroups, includeDirectChats}) -> {includeGroups, includeDirectChats, allowlist, denylist}`. Per type: majority wins (ties: groups on, direct off); empty type keeps `current`. Property-tested against `isChatIncluded`.
  - `writeSelection(paths, rules, all) -> {file, allowlistEntries, denylistEntries, keptUnknown}`. `all` is needed to know which hand-typed name entries to replace. Keeps other keys and comments (yaml Document API), entries are `"<chat id>" # <name>`, atomic temp+rename, idempotent. Unknown hand-written entries stay.
  - `currentSelection(cfg, all) -> Set<id>`.
  - `buildChatRows(store, config) -> ChatRow[]`: all chats, newest `lastMessageAt` first, nulls last, `preselected` = currently included by config.
- `src/daemon/ingest.ts`: `Ingestor.onExcluded?: (msg) => void` (5th ctor arg / public property). Called for messages of excluded chats. The daemon does not set it.
- `src/daemon/link.ts`: `linkAccount({ chooseChats?: (rows: ChatRow[]) => Promise<Set<string>|null>, bufferCap? })`.
  - While settling, excluded-chat messages go to an in-memory `ExcludedBuffer` (cap 50,000, oldest dropped, warning logged with counts only). Never written to disk; cleared in `finally`.
  - After settle, the WA client is closed, then `chooseChats(buildChatRows(...))` is called with DBs open and the lock held.
  - Returned set: writeSelection, reload config, `recomputeIncluded()`, delete stored messages of now-excluded chats (`deleteMessagesOfChats`, one transaction, FTS triggers keep the index), insert buffered messages of now-included chats through the ingestor (mention detection applied). `null`: defaults kept, buffer discarded.
  - The `link` CLI command does not pass `chooseChats`.
- CLI (`src/cli/commands/select.ts`, registered under `chats`):
  - `wa-bridge chats select` (no flags: shows the current selection), `--all`, `--none`, `--set-groups all|none`, `--set-direct all|none`, `--include <chat...>`, `--exclude <chat...>`.
  - `wa-bridge chats include|exclude <name|id>...`.
  - Resolution: id, exact name (case-insensitive), unique substring; ambiguous lists candidates, exit 1.

## Gotchas
- Commander splits flag strings on `|`, so `--groups <all|none>` is silently a boolean flag.
- The parent `chats` listing already has `--all`, `--groups`, `--direct`, and commander lets the parent consume them even after the subcommand name. Hence `select` uses `--set-groups/--set-direct` and reads `--all` through `optsWithGlobals()`.
- `src/cli/index.ts` change: `const chats = program.command('chats')` plus one `registerChatSelection(chats, run, project, io, deps)` line and its import.
