# T14 notes: MCP setup tools + Claude Desktop package

## Data dir
`src/mcp/main.ts`: `--data-dir <dir>` -> `resolveUserPaths(dir)`; `--project <dir>` -> `resolvePaths` (dev); default `resolveUserPaths()`.
`pathsFromArgs`, `realDeps(target: string | DataPaths)`, `runStdio(target, keyStore?, { withHost })` exported. The CLI `mcp` command still calls `runStdio(projectRoot, ...)` without a host (old behaviour). The entry point starts the host (`withHost: true`) after `server.connect`, in the background, and stops it on stdin end, SIGTERM, SIGINT or transport close.

## Host seam (`src/mcp/host.ts`)
`McpDeps.getHost?: () => HostBridge | null`. `HostBridge = { ops(), mintNonce(), openSetup(), acceptRisk(nonce), stop() }`.
`loadRealHost(paths)` does `import('../host/index.js')` (carries a `@ts-ignore` because T12 may be absent; **orchestrator: delete the two comment lines above the import once src/host is merged**). It calls `startHost(paths)` (not awaited) and uses these exports of `src/host/index.ts`:
- `getSetupOps(paths)`, `stopHost()` (specified by T12)
- `HostOps` extras per T12: `mintNonce(): {nonce}`, `openSetup()`, `acceptRisk(nonce)`. Used as-is (no assumed names remain).

## Tools
New model-visible: `open_setup`, `wait_for_sync {timeout_seconds=60}`, `set_chat_inclusion {include?, exclude?}`. `get_status` gained `collector`, `last_live_at` (from `meta.collector_state`, `meta.last_live_at`) and warnings ("Say: set up WhatsApp").
App-only (`_meta.ui.visibility: ['app']`): `setup_state`, `setup_accept_risk {nonce}`, `setup_start_link`, `setup_cancel_link`, `setup_chat_rows`, `setup_submit_selection {selectedIds|null}`, `setup_wait_for_sync {timeoutMs}`. Data goes in `structuredContent`; `content` text is minimal (never qrSvg, never a nonce). Failures: `isError: true` with a plain message.
Resource `ui://wa-bridge/setup.html`: reads `dist/ui/setup.html` (placeholder if missing), injects `<script>window.__WA_NONCE__="..."</script>` right after `<head>`, nonce minted per read.
Also: server `instructions` (20 lines), prompts `daily_brief`, `mentions`, `department_report`.

## Capability detection
`McpServer` is created with `tools.listChanged`, `resources`, `prompts` capabilities. `server.server.oninitialized` (fires on `notifications/initialized`) reads `getClientCapabilities()` and, if `getUiCapability()` (extension `io.modelcontextprotocol/ui`) is present, registers the app-only tools then (tools/list_changed is sent). Clients without it (Claude Code) never see them. `open_setup` checks the same capability at call time: UI -> "panel is shown"; no UI -> `host.openSetup()` (host opens the browser itself) and returns "I opened the setup page in your browser", no URL/token. `createServer(deps, { uiSupported })` forces the decision in tests.
