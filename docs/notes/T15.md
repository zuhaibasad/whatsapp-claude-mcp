# T15 notes: chat metadata

## Store (schema v2)
- `STORE_SCHEMA_VERSION = 2` lives in `src/store/schema.ts` (core `SCHEMA_VERSION` constant still 1; NEED: orchestrator may align). `migrate()` runs v1 then upgrades to v2 in one transaction: chats rebuilt (type CHECK group|direct|channel, `unread_count`, `last_activity_at`), `@newsletter` rows retyped to `channel`, `last_activity_at` backfilled from `last_message_at`, new `contacts` table.
- New Store methods: `upsertContact`, `getContact(idOrPhoneOrLid)`, `linkLid(lid, phoneJid)`, `touchChatActivity(chatId, ts, unreadCount?, included=false)`.
- `Chat` has `lastActivityAt?`, `unreadCount?`. `listChats` sorts by max(activity, last message). `insertMessage` also bumps `last_activity_at`; chat type from JID suffix (`chatTypeFromJid`).

## Adapter events (Baileys rc14 names)
Listened: `chats.upsert`, `chats.update`, `messaging-history.set` (chats, contacts, `lidPnMappings`), `contacts.upsert/update`, `lid-mapping.update` ({lid, pn}), `messages.upsert`.
New WaClient events: `activity {chatId, ts, pushName, senderId}` (every message before filtering, no text), `lid-map {lid, phoneJid}` (also from message `remoteJidAlt`/`participantAlt` and contacts with both ids). `contacts` payload is now `Partial<Contact>[]`. `ChatMeta` has `lastActivityAt?`, `unreadCount?` (seconds; Long handled; -1 unread ignored). Newsletters emit as `channel`; status/broadcast still skipped.

## Ingestor
`onActivity`, `onLidMap` added; `onContacts` persists to the store (in-memory map removed). Wired in `src/daemon/runner.ts` and `src/daemon/link.ts` (one line each, not owned files).

## Config / selection
`include_channels` key (template, load, filter, `writeSelection`, `computeRules` 3 types, CLI `chats select --set-channels all|none`). `matchesQuery(row, q)` and `phoneFromJid` exported from `src/config/selection.ts`; passes `test/fixtures/phone-search-vectors.json` (leading 0 read as 92). `buildChatRows(store: Pick<Store,'listChats'|'getContact'>, config)`.

## Data-dir migration (`src/host/migrate.ts`)
`migrateLegacyDataDir(paths, {keyring, logger, legacyDir?})`, called at the top of `createHost` in `src/host/host.ts` (after `resolveHostDeps`). Only on Windows, default folder, no `WA_BRIDGE_HOME`. Skips if legacy `store.db` or key missing, or new folder has store.db/auth.db. Checkpoints legacy DBs, copies to `.migrate-tmp`, verifies, copies keychain key to the new account, copies missing yaml files and `exports/`, moves auth.db then store.db, writes `meta.migrated_from`. Guarded by a `.migrating` marker (stale after 5 min). Never throws. Old folder untouched. CLI is project-mode only, so no CLI hook; `init.ts` unchanged.
