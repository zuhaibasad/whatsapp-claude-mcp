# T17 notes: picker and setup UX

## What changed (ui/)
- `logic.ts`: `Tab` adds `channels`; `SortMode` (`recent` | `unread`); `formatPhone`, `rowPhone`, `subPhone`, `displayName` (name -> "+92 300 1234567" -> "Unknown contact"); `matchesQuery` (name text, or phone digits ignoring spaces/+/-/brackets, leading 0 = 92, digit matching only for digit-only queries); `sortRows`; `filterRows(rows, tab, query, sort)`; `tabCounts` (All = groups + direct, channels counted apart); `channelCounts`; `selectionHeader(counts, channels?)`; `unreadLabel` (99+ cap); `screenFromSearch`, `initialScreenFrom`, `opensPicker(initial, step)`, `showPermissionsStep(stepBeforeSave, alreadySeen)`.
- `host.ts`: `Host` gains `kind: 'app' | 'browser'` and `initialScreen()`. Panel host sets `app.ontoolresult` before `connect()` and reads `structuredContent.initialScreen` (waits max 800 ms for the first result). Browser host reads `?screen=chats`.
- `main.ts`: 4 tabs with counts, sort toggle, unread pill, phone under name, 📢 for channels, placeholder "Search name or number". Straight-to-picker entry (`entryChats`). New `permissions` screen after the first onboarding save only (in memory, once per panel session). Later-visit/entry saves show "Saved ... Done — you can close this panel."
- `style.css`: `.badge`, `.sortbar`, `.seg`, tabs wrap, names hug the start edge (RTL names no longer jump to the right).
- `dev-mock.ts`: channels, LID chats with only a phone, unread counts (some null, some 99+), interleaved recency. `?host=app` shows the Desktop wording; `?screen=chats` works.
- Mock-only screenshot aids in main.ts (only when `?mock=1`): `tab=`, `q=`, `sort=unread`, `autosave=1`.

## For T15 / T16
- `test/fixtures/phone-search-vectors.json` = `{ vectors: [{query, name, phone, match}] }`; the server `matchesQuery` should satisfy all of it (the UI test already does, with id `x@lid` so only `phone` is used).
- The UI treats channel rows as `type: 'channel'`. Channels are excluded from the "All" tab and have their own tab; the UI shows whatever rows the server returns.
- Save sends all selected ids (including channel ids). `SelectionSummary` is unchanged; channels are not in its counts.
- `whatsapp_setup` must return `structuredContent: { initialScreen: 'chats' | 'auto' }`.

## Behaviour decisions
- Permissions step: shown when the state before Save was `choose_chats` (first-time setup) and not yet shown in this panel session. Desktop wording only for `kind === 'app'`; the browser gets the Claude Code wording. No persistence (the iframe may not allow storage); worst case it shows once per setup run.
- `initialScreen: 'chats'` with state other than done/choose_chats is ignored (normal flow).
