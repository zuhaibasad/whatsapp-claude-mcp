# T20 notes: lifecycle and operations

## Disconnect
- `HostOps.disconnect({ keepData, nonce? })`, `HostOps.mintNonce(kind?: 'accept' | 'disconnect')`, `openSetup(screen?: SetupScreen)`.
- `SetupOps.disconnect` and `diagnose` are now required (edited `src/core/service.ts` as the spec said).
- HTTP: `POST /api/disconnect {keepData:boolean}` needs a browser session (cookie + CSRF) or header `X-Disconnect-Nonce`
  (single-use, 10 min, separate store from the accept nonce). Control token alone: 403. `POST /api/diagnose` takes the control token.
  `POST /api/mint-nonce {kind:'disconnect'}`, `POST /api/open-setup {screen:'disconnect'}` (`/setup?screen=disconnect` survives the redirect).
- MCP: app-only tool `setup_disconnect {nonce, keepData}`; the setup resource now injects `window.__WA_DISCONNECT_NONCE__` next to `__WA_NONCE__`
  (two mints per resources/read). `whatsapp_setup` accepts `screen: "disconnect"`. Model-visible tools stay at 7.
- Flow (HolderCore.disconnectVerified): abort link flow, stop collector, create a client via `waClientFactory`, wait for `open`
  (`deps.disconnectTimeoutMs`, default 20 s), call `unlink()` once (the only logout path), always `close()`.
  Offline/failed: still wipes and sets a notice in `SetupState.error` (step stays `ready_to_link`): "Could not reach WhatsApp; remove the device on your phone: Settings → Linked devices".
  Always: delete auth.db (+wal/shm), qr.png. keepData=true: store link status 'unlinked', reopen dbs, step `ready_to_link`.
  keepData=false: also store.db, config yamls, exports/, backups/, keychain master key; step `needs_accept`. The lock and control server stay.
- UI: "Disconnect WhatsApp" link on both Done variants; confirm screen with two radio options (nothing preselected) and a red button whose label follows the choice.
  `InitialScreen`/`SetupScreen` 'disconnect' handled (`?screen=disconnect`, tool result `initialScreen`).

## Chat notes
- departments.yaml is either the old top-level list or a mapping `{departments: [...], chats: [...]}`; the template now uses the mapping form.
- `loadChatNotes(paths, warnings?)`, `findChatNote(notes, {id,name})` in `src/config`. `chat_note: {department, note}` appears on each chat in
  `whatsapp_brief.new_messages.chats[]` and `whatsapp_read messages` (`chat.chat_note`). Broken yaml never breaks reading.

## Diagnose
`src/host/diagnose.ts` `buildDiagnosis`. Checks: data_dir (exists, MSIX `\Packages\Claude_` warn), keychain, lock_holder, link, schema, collector (+last_live_at),
connection (health_last_frame_at, health_reconnects_24h, health_last_reason; defensive, '' = none), proxy, disk (<500 MB warn), backups.
`whatsapp_status {diagnose:true}` adds `diagnosis`; `wa-bridge doctor [--json]` (new `src/cli/commands/doctor.ts`, registered in cli/index.ts).

## Backups
`src/host/backup.ts`: `backupBeforeMigration(dataDir, master, {toVersion?})` copies store.db/auth.db (after checkpoint) to
`<dataDir>/backups/<ISO>-pre-v<to>/` only when store.db's schema_version < target; keeps 3; writes `meta.last_backup_at`. Called in `HolderCore.openDbs`
before `openDaemonDbs`, and in `migrate.ts` before the moved store is upgraded. Failure is logged, never blocks.
